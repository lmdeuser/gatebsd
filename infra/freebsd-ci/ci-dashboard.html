Release and Installation Flow

  1. Push to master. The pipeline triggers automatically. The dev branch and pull requests run validation only without publishing a package.
  2. Wait for a green run. The validate job checks syntax and unit tests; freebsd-package builds inside a disposable FreeBSD jail, signs, and publishes. Both appear below with logs.
  3. Verify the package. It appears in the releases table marked current with its signature status.
  4. Install. In the GateBSD Web UI: System → Updates. The installer snapshots rollback artifacts and rolls back automatically if post-install checks fail.
Manual install via pkg(8)

The repository is signed. Setting signature_type: pubkey is mandatory so pkg rejects unsigned catalogues. 

# /usr/local/etc/pkg/repos/gatebsd.conf
gatebsd-releases: {
    url: "@@BASE_URL@@/@@PROJECT_SLUG@@/releases/current",
    mirror_type: "none",
    signature_type: "pubkey",
    pubkey: "/usr/local/etc/ssl/certs/pkg.pub",
    enabled: yes
}

# then
pkg update -r gatebsd-releases
pkg upgrade -r gatebsd-releases gatebsd
